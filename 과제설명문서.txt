1. 프로젝트 개요 및 목표
--------------------------------------------------------------------------------

본 프로젝트는 DirectX 12 API를 사용하여 3D 탑다운 슈팅/미로 탐험 게임을 구현한 것이다.
외부 엔진(Unity, Unreal 등)을 사용하지 않고 Win32 API 위에서 DX12를 직접 초기화하고,
행렬 계산·충돌·AI·렌더링 파이프라인을 모두 직접 구현하였다.

주요 구현 목표:
  - DirectX 12 렌더링 파이프라인 직접 구성
  - MSAA(멀티샘플 안티앨리어싱) 적용
  - 하드웨어 인스턴싱을 이용한 대량 오브젝트 고속 렌더링
  - 물리 기반 플레이어 이동 및 AABB 충돌 처리
  - Flow Field 기반 적 AI 경로 탐색
  - DFS 알고리즘 기반 랜덤 미로 생성
  - 1인칭/3인칭 카메라 및 스프링암(Spring Arm) 구현

2. 프로그램 실행 및 조작법
--------------------------------------------------------------------------------

[ 조작키 ]
  W / A / S / D       이동 (카메라 방향 기준)
  Space               점프
  마우스 이동         시점 회전
  마우스 좌클릭       총 발사 (게임 중) / 오브젝트 선택 (타이틀·맵 선택 화면)
  F5                  1인칭 ↔ 3인칭 카메라 전환
  F6                  디버그 카메라 모드 토글 (자유 비행)
  F9                  전체화면 토글
  F1                  AABB 와이어프레임 디버그 시각화 토글
  ESC                 종료

[ 디버그 카메라 조작 (F6 활성화 시) ]
  W / A / S / D       전후좌우 이동
  Q / E               상하 이동
  Shift 누르는 중      이동 속도 2배
  마우스 좌클릭 드래그 시점 회전

[ 초기 창 크기 ]
  1920 × 1080 (WS_OVERLAPPEDWINDOW 윈도우)
  주의: 게임 씬의 투영 행렬은 Aspect를 1280/720으로 하드코딩하여 사용한다.

[ 게임 흐름 ]
  실행 → 타이틀 화면(START 클릭) → 맵 선택(Map1 또는 Map2 클릭) → 게임 시작
  낙사 시 자동 리스폰 (시작 지점으로 복귀)

3. DirectX 12 파이프라인 초기화
--------------------------------------------------------------------------------

DX12는 DX11과 달리 모든 초기화를 개발자가 명시적으로 수행해야 한다.
Framework::Initialize()에서 아래 순서로 진행된다.

[ 초기화 순서 ]

  (1) Debug Layer 활성화
      D3D12GetDebugInterface()로 디버그 컨트롤러를 얻어 EnableDebugLayer()를 호출한다.
      개발 중 DX12 API 오류 시 콘솔에 상세 메시지가 출력된다.

  (2) Device 생성 (InitDirect3D)
      IDXGIFactory → EnumAdapters1()로 하드웨어 GPU 어댑터를 열거·선택한다.
      D3D12CreateDevice()로 Feature Level 11.0 기반의 ID3D12Device를 생성한다.
      Device는 GPU와 통신하는 가상 인터페이스이며 이후 모든 DX12 객체 생성에 사용된다.

  (3) Command Queue / Command List / Command Allocator 생성
      - Command Allocator: 명령 리스트가 기록될 메모리 공간. 프레임 버퍼 수(2개)만큼 생성.
      - Command List: 렌더링 명령(Draw, Barrier 등)을 기록하는 장부.
      - Command Queue: 완성된 명령 리스트를 GPU로 전달하는 통로.
      DX12에서는 CPU가 Command List에 명령을 모두 기록한 뒤 ExecuteCommandLists()로 GPU에 한꺼번에 제출한다.

  (4) Swap Chain 생성 (CreateSwapChain)
      화면에 출력할 백 버퍼 2개(더블 버퍼링)를 관리하는 IDXGISwapChain3를 생성한다.
      스왑 이펙트는 DXGI_SWAP_EFFECT_FLIP_DISCARD를 사용하며, 이는 최신 고성능 방식이다.
      스왑 체인 자체는 SampleDesc.Count = 1로 두고, MSAA는 별도 렌더타겟에서 처리한다.

  (5) Descriptor Heap 생성 (CreateRtvDsvDescriptorHeap)
      Descriptor는 GPU 리소스(버퍼, 텍스처 등)를 어떻게 해석할지 설명하는 구조체이다.
      Heap은 이 Descriptor들을 모아두는 배열이다.
      - RTV Heap (Render Target View): 백 버퍼 2개 + MSAA 렌더타겟 1개 = 3개 슬롯
      - DSV Heap (Depth Stencil View): MSAA 깊이 버퍼 1개 슬롯

  (6) 프레임 버퍼 및 MSAA 렌더타겟 생성 (CreateFrameBuffers)
      스왑 체인에서 GetBuffer()로 백 버퍼 2개를 가져와 RTV를 생성한다.
      추가로 MSAA용 별도 렌더타겟(SampleDesc.Count=4)을 생성한다.
      게임은 MSAA 렌더타겟에 그린 뒤 백 버퍼로 Resolve하는 구조다.

  (7) 깊이 버퍼 생성 (CreateDepthStencilView)
      3D 렌더링에서 앞뒤 관계 판별에 사용되는 깊이 버퍼를 생성한다.
      포맷은 DXGI_FORMAT_D32_FLOAT이며, MSAA와 동일한 Count=4, Quality를 사용한다.

  (8) Fence 생성 (CreateSyncObjects)
      Fence는 CPU와 GPU 간 동기화 신호등이다.
      GPU가 명령 처리를 완료하면 Fence 값을 증가시키고, CPU는 이 값을 확인해 대기한다.
      WaitForGPU()에서 Signal() → WaitForSingleObject()로 완료를 보장한다.

  (9) 셰이더 컴파일 및 파이프라인 상태 객체(PSO) 생성 (CompileShaders)
      → 4절에서 상세 설명

4. 셰이더 및 렌더링 파이프라인 (PSO)
--------------------------------------------------------------------------------

[ HLSL 셰이더 (shaders.hlsl) ]

  정점 셰이더 (vs_main):
    - 입력: 정점 데이터(위치, 법선, 색상) + 인스턴스 데이터(월드 행렬 4행, 틴트 색상)
    - 인스턴스 버퍼에서 전달된 4개의 float4(w0~w3)를 조합해 4x4 월드 행렬을 복원한다.
    - 변환 순서: 로컬 위치 → 월드 변환 → ViewProj 변환 → 클립 공간
      output.position = mul(mul(float4(pos, 1.0), world), viewProj)
    - 법선도 월드 변환을 적용한다 (방향 벡터이므로 w=0).

  픽셀 셰이더 (ps_main):
    - 방향 조명(Directional Light)을 구현한다.
    - 광원 방향 L = normalize(1, 1, -1) (고정 단방향 조명)
    - 람베르트 확산 반사: diffuse = max(dot(N, L), 0) * 0.8
    - 주변광(Ambient): 0.2 (어두운 곳도 완전히 검어지지 않도록)
    - 최종 색상: vertex_color * tint_color * (ambient + diffuse)

[ Root Signature ]
  셰이더가 사용할 데이터의 바인딩 구조를 정의한다.
  슬롯 b0에 32비트 상수 16개(viewProj 행렬)를 직접 전달한다.
  텍스처가 없으므로 SRV Descriptor Table은 사용하지 않는다.

[ Input Layout ]
  두 개의 Slot으로 나뉜다:
  - Slot 0 (PER_VERTEX_DATA): 정점별 데이터 — 위치(12B), 법선(12B), 색상(16B) = 40B stride
  - Slot 1 (PER_INSTANCE_DATA, InstanceDataStepRate=1): 인스턴스별 데이터
    월드 행렬 4행(각 16B = 64B) + 틴트 색상(16B) = 80B stride (sizeof(InstanceData))

[ Pipeline State Object (PSO) ]
  렌더링에 필요한 모든 상태를 하나의 객체로 묶은 것이다.
  - FillMode: SOLID (면 채우기)
  - CullMode: BACK (뒷면 컬링 — 내부가 안 보이는 면은 그리지 않음)
  - DepthEnable: TRUE, DepthFunc: LESS (가까운 것이 앞에 보임)
  - SampleDesc.Count = 4 (MSAA 4x)
  - RTVFormats: DXGI_FORMAT_R8G8B8A8_UNORM

5. 프레임 렌더링 루프
--------------------------------------------------------------------------------

매 프레임 Framework::Render()가 다음 순서로 실행된다.

  [1] Command Allocator Reset → Command List Reset
      백 버퍼 인덱스를 GetCurrentBackBufferIndex()로 확인하고,
      해당 프레임의 Allocator와 List를 초기화한다.

  [2] 리소스 배리어: → RENDER_TARGET
      MSAA 렌더타겟을 RENDER_TARGET 상태로 전환한다.
      (이전 프레임에서 RESOLVE_SOURCE 상태였으므로 전환이 필요)
      깊이 버퍼도 DEPTH_WRITE 상태로 전환한다.
      상태 추적 변수(mMsaaRTState, mDepthStencilState)로 불필요한 전환을 방지한다.

  [3] Clear & OMSetRenderTargets
      MSAA 렌더타겟을 배경색(진한 남색)으로 클리어하고, 깊이 버퍼를 1.0으로 클리어한다.
      렌더타겟과 깊이 버퍼를 OMSetRenderTargets()으로 바인딩한다.

  [4] Viewport / Scissor 설정, 씬 렌더링
      전체 화면 크기로 뷰포트와 시저 렉트를 설정한다.
      SceneManager::Render()를 호출해 활성 씬의 모든 오브젝트를 그린다.

  [5] MSAA Resolve
      MSAA 렌더타겟(4x 멀티샘플) → 백 버퍼(1x)로 ResolveSubresource()를 호출한다.
      이 과정에서 4개의 샘플을 평균 내어 안티앨리어싱 효과를 적용한다.
      - MSAA RT: RENDER_TARGET → RESOLVE_SOURCE
      - 백 버퍼: PRESENT → RESOLVE_DEST → (Resolve 후) PRESENT

  [6] ImGui 렌더링
      백 버퍼를 다시 RENDER_TARGET으로 전환한 뒤 ImGui UI를 그린다.
      ImGui는 MSAA를 거치지 않고 최종 백 버퍼에 직접 그린다.

  [7] Present
      백 버퍼를 PRESENT 상태로 전환하고, mCommandList->Close() → ExecuteCommandLists() → Present(0,0).
      WaitForGPU()로 CPU가 GPU 완료를 기다린다 (단순 Fence 동기화).

6. OBJ 파일 로딩 (OBJLoader)
--------------------------------------------------------------------------------

OBJLoader::Load()는 .obj 파일을 한 줄씩 읽어 정점/인덱스 데이터를 구성한다.

[ 파싱 과정 ]
  (1) "v x y z"  라인 → positions 배열에 XYZ 추가
  (2) "vn nx ny nz" 라인 → normals 배열에 법선 추가
  (3) "f v1/t1/n1 v2/t2/n2 v3/t3/n3" 라인 → 삼각형 면 파싱
      각 면의 정점 정보를 '/'로 분리해 위치 인덱스(posIdx)와 법선 인덱스(normIdx)를 추출.
      텍스처 좌표(t)는 파싱만 하고 사용하지 않는다.

[ 정점 버퍼 구성 ]
  .obj는 위치와 법선이 별도 인덱스를 가지지만, DX12 정점 버퍼는 단일 인덱스만 사용한다.
  따라서 면(f)의 각 항목을 독립적인 OBJVertex로 펼쳐서 저장한다.
  결과적으로 인덱스는 0, 1, 2, 3, ... 순서의 단순 시퀀스가 된다.

[ AABB 센터링 ]
  로드 완료 후 모든 정점의 AABB 중심(cx, cy, cz)을 계산해 각 정점에서 빼준다.
  이렇게 하면 오브젝트의 로컬 원점이 메쉬의 중심에 위치해 SetPosition/SetScale이 직관적으로 동작한다.

[ OBJVertex 구조체 ]
  struct OBJVertex {
      float x, y, z;       // 위치 (12 bytes)
      float nx, ny, nz;    // 법선 (12 bytes)
      float r, g, b, a;    // 색상 (16 bytes)
  };                       // 총 40 bytes

[ 사용하는 OBJ 파일 목록 ]
  오브젝트       파일명         BakeScale    BakeRotation    초기 색상
  ---------      ----------     ----------   ------------    ---------
  Player         Pacman.obj     0.0025 균일  Y=180도         노란색 (1,1,0)
  Gun            AK-74.obj      0.001  균일  Y=270도         초록색 (0,1,0)
  Enemy          Enemy.obj      공유 메쉬    X=-90, Y=+90    빨간색 (1,0,0)
  Title          TITLE.obj      씬에서 지정  Y=90도          기본(회색)
  Start          START.obj      씬에서 지정  Y=90도          기본(회색)
  Map1/Map2      MAP1/2.obj     씬에서 지정  Y=90도          기본(회색)
  Crosshair      코드 직접 정의 —            —               흰색 (1,1,1)
  Cube           cube.obj       —            —               맵별 SetColor() 지정
  Item_ATK       ATK.obj        0.01 균일    —               연어색 (1.0, 0.55, 0.55)
  Item_HP        HP.obj         0.01 균일    —               연두색 (0.55, 1.0, 0.55)
  Item_SPEED     SPEED.obj      0.01 균일    —               하늘색 (0.55, 0.75, 1.0)

  Crosshair는 .obj 파일 없이 코드에서 8개 정점(가로선 4개 + 세로선 4개)을 직접 정의한다.
  Enemy는 공유 메쉬(LoadSharedMesh)에서 BakeRotation 후 빨간색으로 염색한다.

7. 행렬(Matrix) 계산 및 변환
--------------------------------------------------------------------------------

[ SRT 행렬 (오브젝트 → 월드 변환) ]
  GameObject::Update()에서 매 프레임 계산된다:
    S = XMMatrixScaling(scale.x, scale.y, scale.z)
    R = XMMatrixRotationRollPitchYaw(rotation.x, rotation.y, rotation.z)
    T = XMMatrixTranslation(position.x, position.y, position.z)
    world = S * R * T   (스케일 → 회전 → 이동 순서)

  결과를 XMFLOAT4X4 worldMatrix에 저장한다.
  DirectXMath는 Row-major 행렬을 사용하므로 Transpose 없이 저장한다.

[ BakeScale / BakeRotation ]
  일부 오브젝트(Player, Gun)는 OBJ 로드 직후 정점 좌표 자체에 스케일/회전을 미리 굽는다.
  이후 scale = {1,1,1} 로 두므로, worldMatrix 계산에서 스케일 행렬이 항등 행렬이 된다.
  장점: 물리 계산 시 scale을 고려할 필요가 없어진다.

[ View 행렬 ]
  XMMatrixLookToLH(camPos, camForward, worldUp) 으로 계산한다.
  카메라 위치와 바라보는 방향으로부터 월드 → 카메라 공간으로의 변환 행렬을 생성한다.

[ Projection 행렬 ]
  XMMatrixPerspectiveFovLH(FOV, AspectRatio, Near, Far)
  게임 씬: FOV=70도, Aspect=1280/720, Near=0.1, Far=1000
  타이틀/맵선택 씬: FOV=45도, Near=0.1, Far=100

[ ViewProj 전달 방식 ]
  Root Signature에서 b0에 16개의 32bit 상수를 등록했다.
  매 Draw Call 전에 SetGraphicsRoot32BitConstants()로 viewProj 행렬을 전달한다.
  행렬을 GPU에 전달할 때는 XMMatrixTranspose()를 적용한다.
  (DX12 HLSL은 Column-major를 기대하므로 Row-major의 CPU 행렬을 전치해서 전달)

[ 인스턴스 버퍼에서의 월드 행렬 ]
  인스턴싱 시에는 월드 행렬을 인스턴스 버퍼에 넣어 전달한다.
  셰이더에서는 float4x4 world = float4x4(w0, w1, w2, w3)로 복원하며,
  HLSL의 mul(pos, world) 호출에서 row vector 방식으로 곱한다.

8. 하드웨어 인스턴싱 (Hardware Instancing)
--------------------------------------------------------------------------------

동일한 메쉬를 수백~수천 개 그릴 때 Draw Call 하나로 처리하는 기법이다.
일반적인 방식(Draw Call per Object)은 CPU 오버헤드가 크지만, 인스턴싱은 GPU에서 병렬 처리된다.

[ 적용 대상 ]
  - Cube: Map1 2,601개 / Map2 1,681개  (정적 인스턴싱, 초기화 시 1회 빌드)
  - Enemy: 수십~수백 개  (동적 인스턴싱, 매 프레임 위치 갱신)
  - Item_ATK / Item_HP / Item_SPEED: 각 10개  (동적 인스턴싱)

[ 구조 ]
  인스턴스 버퍼에는 InstanceData 배열이 저장된다:
    struct InstanceData {
        XMFLOAT4X4 world;   // 월드 행렬 (64 bytes)
        XMFLOAT4   color;   // 틴트 색상 (16 bytes)
    };                      // 총 80 bytes

  Input Layout의 Slot 1이 이 버퍼를 읽으며, InstanceDataStepRate=1이므로
  DrawIndexedInstanced() 호출 시 인스턴스마다 한 칸씩 전진한다.

[ Cube 정적 인스턴싱 과정 ]
  (1) BuildInstanceBuffer(device, cubes): 큐브 배열을 순회하며 각 큐브의 worldMatrix와 mColor를
      InstanceData 배열에 채우고 GPU 업로드 힙 버퍼를 생성한다.
      큐브는 정적(이동 없음)이므로 초기화 시 한 번만 빌드한다.
  (2) RenderBatch(commandList): 공유 메쉬(VB/IB)를 Slot 0에,
      인스턴스 버퍼를 Slot 1에 바인딩하고 DrawIndexedInstanced(indexCount, instanceCount)를 호출한다.

[ Enemy 동적 인스턴싱 과정 ]
  (1) BuildInstanceBuffer(device, maxCount): 최대 적 수만큼 업로드 버퍼를 미리 할당한다.
  (2) RenderBatch(commandList, enemies): 매 프레임 살아있는 적의 worldMatrix를 업로드 버퍼에 쓰고
      DrawIndexedInstanced로 한 번에 그린다.

[ 단일 오브젝트(비-배치) 처리 ]
  Player, Gun, Bullet 등 개수가 적은 오브젝트는 GameObject::Render()를 통해 개별 Draw Call로 그린다.
  이 경우에도 인스턴스 버퍼 1개짜리(단일 인스턴스 버퍼)를 사용해 셰이더 입력 구조를 통일한다.

9. GPU 버퍼 관리 (더티 플래그 패턴)
--------------------------------------------------------------------------------

DX12에서 CPU 데이터를 GPU에 올리는 과정은 명시적이며 비용이 있다.
불필요한 업로드를 막기 위해 더티 플래그(mVBDirty, mIBDirty)를 사용한다.

[ 버퍼 구조 (이중 버퍼) ]
  - Upload Heap (CPU 가시): CPU가 직접 Map()/Unmap()으로 쓸 수 있는 버퍼.
  - Default Heap (GPU 전용): GPU가 빠르게 읽을 수 있는 버퍼. CPU에서 직접 쓸 수 없다.

[ 업로드 흐름 ]
  (1) 정점 데이터 변경 시 UpdateVertexBuffer() 호출 → Upload Heap에 memcpy → mVBDirty = true
  (2) Render() 시 UploadBufferIfDirty() 호출:
      - 배리어: Default Heap → COPY_DEST 상태로 전환
      - CopyBufferRegion(): Upload → Default Heap으로 복사
      - 배리어: COPY_DEST → VERTEX_AND_CONSTANT_BUFFER 상태로 전환
      - mVBDirty = false (다음 프레임부터 재업로드 안 함)

이 방식을 통해 정적 오브젝트(Cube 등)는 초기화 이후 단 한 번만 업로드된다.

11. 랜덤 미로 생성 알고리즘
--------------------------------------------------------------------------------

[ 알고리즘: DFS(재귀적 백트래킹, Recursive Backtracking) ]

  모든 셀을 벽(0)으로 초기화한 후, 시작 셀에서 깊이 우선 탐색을 시작한다.

  CarvePath(r, c):
    1. 현재 셀을 통로(1)로 표시
    2. 상하좌우 4방향을 랜덤 순서로 섞음 (Shuffle)
    3. 각 방향에 대해 2칸 떨어진 셀이 유효한 미방문 셀이면:
       - 중간 셀(벽)을 통로로 표시 (두 셀 사이 벽 제거)
       - 재귀 호출 CarvePath(nr, nc)
    4. 모든 방향 탐색 완료 시 백트래킹 (재귀 반환)

  2칸씩 이동하는 이유: ODD 인덱스(1,3,5...) 셀이 방(chamber)이고
  짝수 인덱스 셀이 벽과 통로 사이의 경계가 되도록 그리드를 설계했기 때문이다.

[ Map1 vs Map2 상세 비교 ]

              Map1                         Map2
  그리드      51×51 (2,601셀)              41×41 (1,681셀)
  맵 구조     순수 DFS 미로                DFS 미로 + 8개 오픈 룸
  벽 높이     Y 스케일 3.0                 Y 스케일 4.0
  벽 색상     진회색 (0.2, 0.2, 0.2)       어두운 파란색 (0.1, 0.15, 0.4)
  바닥 색상   연회색 (0.8, 0.8, 0.8)       모래색 (0.85, 0.65, 0.35)
  적 생성확률 20% (uid <= 2, 범위 1~10)    5% (enemy_uid <= 5, 범위 1~100)
  아이템      없음                         ATK/HP/SPEED 각 10개
  스폰 위치   (-48, 2, -48)                (-38, 0, -38)

  CarveRoom(): 지정된 행/열 범위 내의 모든 셀을 통로로 뚫어 넓은 방을 만든다.
  Map2의 오픈 룸 8개: 상단 코너 3개, 중단 코너 2개, 센터, 하단 코너 1개 등
  코너마다 5×5 크기의 넓은 광장이 생성되어 전투 공간을 제공한다.

[ 3D 배치 ]
  sMaze[row][col] == 0이면 벽 Cube, 1이면 바닥 Cube를 배치한다.
  각 Cube는 SetPosition(col*spacing - offset, y, row*spacing - offset)으로 그리드 좌표를 월드 좌표로 변환한다.

12. 플레이어 물리 및 AABB 충돌
--------------------------------------------------------------------------------

[ 좌표계 ]
  Y축이 위 방향(up)이며, 중력은 Y 음의 방향으로 작용한다.

[ 마우스 룩 ]
  매 프레임 화면 중앙(창 클라이언트 중심)으로 커서를 강제 이동시키고,
  이전 위치와의 픽셀 차이를 각도로 변환한다:
    mPitch += (curY - centerY) * 0.002f
    mYaw   += (curX - centerX) * 0.002f
  이 방식으로 커서가 화면 밖으로 벗어나지 않으면서 무한 회전이 가능하다.
  디버그 모드(F6) 진입 시 mFirstMouse = true로 초기화해 첫 프레임 점프를 방지한다.

[ 수평 이동 ]
  플레이어의 Yaw(수평 회전각)로부터 전방 벡터와 우방 벡터를 계산한다:
    rotM = XMMatrixRotationY(yaw)
    fwdF = TransformCoord(0,0,1, rotM)   // Z축을 Yaw로 회전
    rgtF = TransformCoord(1,0,0, rotM)   // X축을 Yaw로 회전
  WASD 입력에 따라 fwdF, rgtF를 조합해 수평 속도(velX, velZ)를 계산하고
  position.x += velX * dt, position.z += velZ * dt로 이동한다.

[ 수직 물리 ]
  매 프레임 중력 가속도를 누적한다:
    mVelocityY += kGravity * dt   (kGravity = -20.0)
  낙하 속도 하한: mVelocityY = max(mVelocityY, -30.0)
  점프: mOnGround && Space → mVelocityY = kJumpSpeed (8.0), mOnGround = false

[ AABB 충돌 해결 방식: 분리 축 정리(SAT) 기반 ]
  충돌 해결을 수평(ResolveHorizontal)과 수직(ResolveVertical) 두 패스로 분리한다.
  이 분리가 중요한 이유: 통합 처리 시 대각선 충돌에서 어느 축으로 밀어야 하는지 모호해지기 때문.

  ResolveHorizontal():
    각 콜라이더와 플레이어 AABB의 각 축 침투량(dx, dy, dz)을 계산:
      dx = (extA.x + extB.x) - |cenA.x - cenB.x|
      dy = (extA.y + extB.y) - |cenA.y - cenB.y|
      dz = (extA.z + extB.z) - |cenA.z - cenB.z|
    하나라도 0 이하면 충돌 없음 → 스킵.
    dy <= min(dx, dz)이면 수직 충돌이 주 축 → 수평 패스에서 스킵.
    dx < dz이면 X축 방향으로, 아니면 Z축 방향으로 플레이어를 밀어낸다.

  ResolveVertical():
    dy <= min(dx, dz) 조건인 경우만 처리 (수직이 주 축인 충돌).
    플레이어 중심이 콜라이더 위에 있으면 착지(position.y += dy, mOnGround = true).
    아래에 있으면 천장 충돌(position.y -= dy, mVelocityY = 0).

[ 물리 AABB 계산 ]
  ComputePhysicsAABB():
    BakeScale 후 scale={1,1,1}이므로 world = RotY(yaw) * Trans(position)
    mLocalAABB.Transform(out, world)으로 월드 AABB를 계산한다.
    worldMatrix 갱신 전에도 호출 가능하므로 물리 연산과 렌더링이 독립적이다.

[ 자동 계단 오르기 (Auto-Step) ]
  ResolveHorizontal()에서 수평 충돌이 감지되면, 추가 조건을 검사한다:
    playerBottom = p.Center.y - p.Extents.y  // 플레이어 발 높이
    obstacleTop  = c.Center.y + c.Extents.y  // 장애물 상단 높이
    stepH = obstacleTop - playerBottom        // 올라가야 할 높이
  조건: mOnGround == true && stepH > 0 && stepH <= kStepHeight(0.45)
  조건 충족 시 position.y를 stepH만큼 올려 장애물 위로 자동 이동한다.
  이후 ResolveVertical에서 자연스럽게 장애물 위면에 착지 처리된다.

[ 낙사 리스폰 ]
  Map1/Map2Scene::Update()에서 매 프레임 확인:
    if (mPlayer->GetPosition().y < -15.0f) → Respawn(spawnPos)
  Respawn(): position = spawnPos, mVelocityY = 0, mOnGround = false

[ 플레이어 스탯 ]
  초기 체력(HP)    : 100 / 최대 체력: 100
  초기 공격력(ATK) : 20
  초기 이동속도    : 5.0
  무적 시간        : 피격 후 1.0초 동안 무적 (mInvTimer > 0이면 TakeDamage 무시)
  적 접촉 피격량   : 10 (살아있는 적 AABB와 겹치는 매 프레임마다)


--------------------------------------------------------------------------------
13. 카메라 시스템
--------------------------------------------------------------------------------

카메라는 Camera 클래스의 정적 멤버로 관리된다.

[ 1인칭 모드 ]
  camPos = playerPos (플레이어 위치와 동일)
  마우스 이동으로 Pitch/Yaw를 갱신하고,
  fwd = TransformCoord(0,0,1, pitchM * rotM)으로 바라보는 방향을 계산한다.
  Pitch 제한 없음 (위아래 자유 회전).

[ 3인칭 스프링암 (Spring Arm) ]
  언리얼 엔진의 Spring Arm 컴포넌트와 동일한 동작을 구현한다.
  벽과 플레이어 사이에 카메라가 끼는 것을 방지한다.

  pivot = playerPos + (0, 0.5, 0)    // 팔의 기준점 (kPivotHeight = 0.5)
  armDir = -fwd (정규화됨)            // pivot에서 카메라 방향 (플레이어 뒤쪽)
  idealPos = pivot + armDir * 2.0    // 이상적인 카메라 위치 (kArmLength = 2.0)

  레이캐스트:
    pivot에서 armDir 방향으로 2.0 거리만큼 모든 콜라이더와 BoundingBox::Intersects() 검사.
    교차 지점이 있으면 actualLength = min(actualLength, dist - 0.15)로 단축.
    finalPos = pivot + armDir * actualLength

  카메라는 항상 pivot(플레이어 머리)을 향해 lookDir을 재계산한다.

  BoundingBox::Intersects(Origin, Direction, Dist):
    DirectX 내장 함수로 Ray-AABB 교차 검사를 수행한다.
    Dist는 원점에서 교차점까지의 거리를 반환한다.

[ 1인칭 시 플레이어 메쉬 숨기기 ]
  1인칭 모드에서 플레이어 자신의 메쉬가 카메라를 가리므로 렌더링을 건너뛴다.
  Map1Scene::Render()와 Map2Scene::Render() 양쪽 모두에서 아래 코드로 처리한다:
    for (const auto& obj : mGameObjects) {
        Player* playerPtr = dynamic_cast<Player*>(obj);
        if (playerPtr && Camera::sMode == eCameraMode::FirstPerson)
            continue;
        obj->Render(...);
    }

[ 크로스헤어 스크린-스페이스 렌더링 ]
  1인칭 모드에서만 렌더링되는 화면 고정 조준선이다.

  핵심 기법: viewProj를 단위 행렬(Identity)로 설정
    → 정점 좌표가 NDC 공간에 그대로 사용된다.
    → 카메라가 어디를 향하든 항상 화면 정중앙에 고정된다.

  정점 구성 (8개, LINELIST 토폴로지):
    가로선: (-size, 0) → (-gap, 0)  /  (gap, 0) → (size, 0)
    세로선: (0, size)  → (0, gap)   /  (0, -gap) → (0, -size)
    (size=0.025, gap=0.005 → 중앙 빈 공간이 있는 십자형)

  인덱스 4쌍(8개 인덱스)으로 DrawIndexedInstanced 1회 호출.
  렌더링 후 D3D_PRIMITIVE_TOPOLOGY_TRIANGLELIST로 토폴로지를 복원한다.

[ 디버그 카메라 ]
  debugMode = true일 때 활성화.
  LButton 드래그로 camYaw/camPitch를 갱신하고 WASD/QE로 자유 비행.
  Shift를 누르는 동안 이동 속도 2배.


--------------------------------------------------------------------------------
14. 마우스 레이 피킹 (Ray Picking)
--------------------------------------------------------------------------------

타이틀 화면과 맵 선택 화면에서 3D 오브젝트를 마우스로 클릭하는 기능이다.

[ 과정 ]
  (1) 마우스 스크린 좌표 → NDC 좌표 변환:
        ndcX = (2 * mouseX / screenW) - 1
        ndcY = 1 - (2 * mouseY / screenH)

  (2) NDC → 월드 공간 역변환:
        invVP = inverse(view * proj)
        nearPt = TransformCoord((ndcX, ndcY, 0), invVP)  // Near plane의 월드 위치
        farPt  = TransformCoord((ndcX, ndcY, 1), invVP)  // Far plane의 월드 위치

  (3) 레이 생성:
        rayOrigin = camPos
        rayDir = normalize(farPt - nearPt)

  (4) AABB와 교차 검사:
        BoundingBox::Intersects(rayOrigin, rayDir, dist)
        교차하면 해당 씬으로 전환.

  Z=0과 Z=1의 NDC 좌표를 역변환해서 Ray를 구성하는 방식이 핵심이며,
  이는 뷰포트→클립→NDC→월드 변환의 역순이다.


--------------------------------------------------------------------------------
15. 적 AI — Flow Field 경로 탐색
--------------------------------------------------------------------------------

[ 개요 ]
  개별 길 찾기(A*, BFS per enemy) 대신 Flow Field를 사용한다.
  플레이어 위치를 목적지로 한 번의 BFS로 거리 맵을 만들고,
  모든 적이 이 맵을 공유해 O(1)로 다음 이동 방향을 결정한다.

[ Flow Field 생성 (BFS) ]
  (1) 플레이어 그리드 좌표를 계산:
        pRow = round((pPos.z + offset) / spacing)
        pCol = round((pPos.x + offset) / spacing)
  (2) 플레이어 위치를 큐에 넣고 거리 0으로 초기화.
  (3) BFS: 인접 셀(상하좌우)이 통로이고 미방문이면 거리 += 1로 갱신.
  (4) 결과: mFlowField[row][col] = 플레이어까지의 최단 경로 거리 (−1이면 미도달)

  매 프레임 플레이어 위치가 바뀌므로 UpdateFlowField()를 매 프레임 호출한다.
  51×51 = 2,601 셀, 41×41 = 1,681 셀이므로 BFS 비용은 무시할 수 있는 수준이다.

[ 적 이동 ]
  GetNextWaypoint():
    현재 셀의 인접 4방향 중 mFlowField 값이 가장 작은 방향으로 이동한다.
    (거리가 작을수록 플레이어에 가까움)
    해당 셀의 중심 월드 좌표를 반환한다.

  감지 범위(mDetectRange): 한 번이라도 플레이어가 범위에 들어오면 mIsChasing = true로 영구 추격.

[ 적끼리 분리 (SeparateFromEnemies) ]
  같은 그룹의 적끼리 겹치지 않도록 밀어낸다.
  분리 반경(kSepRadius = 0.8)보다 가까우면 차이 벡터 방향으로 (겹침량 * 0.5)만큼 밀어낸다.

[ 적 수평 이동 전용 (No Gravity) ]
  적은 중력의 영향을 받지 않는다.
  GetNextWaypoint()에서 반환하는 방향 벡터의 Y를 0으로 고정한다:
    XMVECTOR toWP = XMVectorSetY(wp - pos, 0.0f);
  따라서 적은 항상 수평면에서만 이동하며, 공중에 뜬 상태로 이동할 수 있다.

[ 적 벽 충돌 알고리즘 (플레이어와 차이점) ]
  플레이어는 수평/수직 패스를 분리하지만, 적은 단일 패스로 처리한다.
  ResolveWallCollision()에서 모든 콜라이더를 순회하며 3축 침투량을 계산 후
  가장 작은 축 방향으로 한 번에 밀어낸다(최소 침투 벡터, MTV):
    dx <= dy && dx <= dz → X축으로 push
    dy <= dx && dy <= dz → Y축으로 push
    그 외                → Z축으로 push
  자동 계단 오르기나 착지 처리가 없어 구현이 단순하다.

[ 적 스탯 ]
  초기 체력(HP)  : 100
  이동 속도      : 3.0
  감지 범위      : 10.0 (플레이어가 이 거리 안에 들어오면 영구 추격 시작)
  분리 반경      : 0.8 (다른 적과 겹치지 않도록 밀어내는 최소 거리)


--------------------------------------------------------------------------------
16. 총 및 총알 오브젝트 풀링
--------------------------------------------------------------------------------

[ Gun 오브젝트 ]
  Player에 AttachTo()로 연결된다.
  매 프레임 플레이어의 위치, Yaw, Pitch를 읽어 오른손 앞쪽 오프셋 위치에 배치한다:
    gunPos = playerPos + right * 0.35 + up * (-0.20) + forward * 0.40
  GetMuzzlePosition(): 총구 위치 = gun 위치 + forward * 0.5

[ 오브젝트 풀링 (Object Pooling) ]
  총알 10개를 초기화 시 미리 생성해두고 mBullets 벡터에 보관한다.
  발사 시 IsActive() == false인 총알을 찾아 Fire()로 재활성화한다.
  총알이 벽에 맞거나 적에 맞거나 수명(3초)이 다하면 Deactivate()로 비활성화한다.
  새 오브젝트를 동적으로 생성/삭제하는 것보다 메모리 할당 비용이 없어 효율적이다.

[ 총알 스탯 ]
  발사 속도(speed) : 30.0 (Fire() 기본값)
  수명(lifetime)   : 3.0초 (mLife가 0 이하면 Deactivate)
  데미지(damage)   : 플레이어 현재 ATK값 전달 (기본값 20)
  메쉬             : sphere.obj, BakeScale 0.2 균일, 노란색 (1, 1, 0)

[ 총알 충돌 처리 ]
  Bullet::Update()에서 이동 후 즉시 모든 콜라이더(벽)와 AABB 교차 검사를 수행한다.
  Map1/Map2Scene의 CheckBulletEnemyCollision()에서 활성 총알과 살아있는 적의 AABB를 교차 검사한다.
  충돌 시 b->Deactivate(), e->TakeDamage(b->GetDamage()).


--------------------------------------------------------------------------------
17. 아이템 시스템 (Map2 전용)
--------------------------------------------------------------------------------

Item 추상 기반 클래스에서 3종의 아이템이 파생된다:
  - Item_ATK:   플레이어 공격력 증가
  - Item_HP:    플레이어 체력 회복
  - Item_SPEED: 플레이어 이동 속도 증가

각 타입별로 공유 메쉬(LoadSharedMesh)와 인스턴스 버퍼를 유지해 배치 렌더링한다.

[ 픽업 판정 ]
  CheckItemPickup()에서 매 프레임 활성 아이템을 순회:
    XZ 평면 거리 = sqrt((px-ix)² + (pz-iz)²) < 2.0 이면 OnPickup(player) 호출.

[ 아이템 효과 ]
  Item_ATK   : 플레이어 ATK += 5
  Item_HP    : 플레이어 HP  += 10 (최대 100 상한)
  Item_SPEED : 플레이어 MoveSpeed += 1.0

[ 아이템 회전 애니메이션 ]
  Item::Update()에서 활성 아이템은 매 프레임 Y축으로 회전한다:
    rotation.y += 2.0f * dt  (약 115도/초, 시각적 식별 용이)

[ 스폰 ]
  SpawnItems(): 미로의 모든 통로 셀을 수집하고, 스폰 지점 근처(반경 5칸 이내) 제외 후
  셔플하여 랜덤 위치에 30개(ATK 10, HP 10, SPEED 10)를 배치한다.
  아이템 인스턴스 버퍼는 타입당 최대 100개 분량을 미리 할당한다.


--------------------------------------------------------------------------------
18. ImGui UI
--------------------------------------------------------------------------------

ImGui는 별도의 쉐이더나 버퍼 없이 DX12 위에 즉시 모드(Immediate Mode) UI를 렌더링한다.
Framework::Update()에서 NewFrame()을 호출하고, Framework::Render()에서 ImGui::Render()로 그린다.
현재 게임 씬(Map1/Map2)에는 ImGui::Begin/Text 등의 호출이 없으므로 실제로 화면에 표시되는 UI는 없다.
(ImGui 인프라만 초기화된 상태이며, 스탯 표시 등은 추후 추가 가능한 구조)

ImGui는 MSAA 렌더타겟이 아닌 최종 백 버퍼에 직접 그린다.
(MSAA를 거치지 않아도 UI는 텍스트/사각형이라 계단 현상이 거의 없음)

렌더링 순서:
  [MSAA RT] → 씬 렌더링 → Resolve → [백 버퍼] → ImGui 렌더링 → Present

19. 추가 구현 내용 요약
--------------------------------------------------------------------------------

  (1) 자동 계단 오르기 (Auto-Step)
      수평 충돌 시 발 높이에서 kStepHeight(0.45) 이하의 장애물을 자동으로 오른다.
      자연스러운 이동감과 미로 탐색 편의성을 향상시킨다.

  (2) 스프링암 카메라 (Spring Arm)
      3인칭 모드에서 카메라와 플레이어 사이에 벽이 있으면 카메라가 자동으로 당겨진다.
      Ray-AABB 교차 검사를 활용해 언리얼 엔진의 Spring Arm 동작을 재현했다.

  (3) MSAA 4x 안티앨리어싱
      별도의 멀티샘플 렌더타겟을 유지하고 매 프레임 백 버퍼로 Resolve한다.
      게재자 상태 추적 변수로 중복 배리어 전환을 방지했다.

  (4) 더티 플래그 기반 GPU 버퍼 관리
      데이터 변경 시에만 Upload → Default Heap 복사를 수행한다.
      정적 오브젝트(Cube)는 초기화 이후 GPU 업로드가 발생하지 않는다.

  (5) 마우스 레이 피킹 기반 UI
      씬 전환을 화면상의 3D 오브젝트 클릭으로 처리한다.
      NDC → 월드 역변환 후 AABB 교차로 구현했다.

  (6) Flow Field 기반 적 경로 탐색
      전체 맵에서 BFS를 한 번 실행하면 모든 적이 O(1)으로 방향을 결정한다.
      적이 아무리 많아도 경로 탐색 비용이 증가하지 않는다.

  (7) 낙사 리스폰
      Y 좌표가 -15.0 미만이면 플레이어를 시작 지점으로 즉시 복귀시킨다.

  (8) 전체화면 토글 (F9)
      IDXGISwapChain::SetFullscreenState()와 OnResize()를 연동해
      전체화면 전환 후 뷰포트/버퍼 크기를 즉시 갱신한다.
